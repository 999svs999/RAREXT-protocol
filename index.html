A name is not a receipt. A hosted API tells you which model family answered. RAREXT names the exact weight bytes, the engine bytes, and the trace.

How it works

Four steps. None of them asks you to believe a server.

The model and the engine are separate content-addressed artifacts. A provider fetches both, verifies every shard, and runs exactly what it fetched. You get bytes you can check.

  1. 01

    Commit the weights and the engine

    Each is sharded into RAREXT blobs under one digest. A provider that cannot reproduce the digest refuses to serve the model — not “logs a warning”, refuses.

  2. 02

    Decode deterministically

    Greedy or sampled, with temperature, top-k, top-p, min-p, typical-p, penalties, logit bias, and a stop set. The seed is part of the claim, so a run is repeatable.

  3. 03

    Record the trace, not just the text

    Every answer carries the token ids it decoded, per-token logprobs where requested, and the bound it ran inside. The text is a rendering of the trace.

  4. 04

    Verify by recomputation

    A reader re-derives the result from the trace, the model, and the seed. Lossy work is a measured distance against a committed reference — never an assertion.

Verification is not truth. Recomputing a run proves the bytes and the execution are what was claimed. It does not prove the model is correct, safe, or unbiased. RAREXT is built to say exactly that, and no more.

Limits

The claim says what it does not cover.

RAREXT is a runtime and a protocol, not a model. Its quality ceiling is the model an operator commits. Today that is a 0.5B model class on this host, and the ladder says so in public.

  • Small models, for now. The shipped class is 1G; 6/7/8 GB need a host that can hold them.
  • Slower than native. The JavaScript engine is ~30× slower than llama.cpp here, and it is not claimed to compete.
  • Text only. No vision, audio, image, speech, or video path exists.
  • Software enclave. The trust anchor is a shipped key, not fused silicon; a hardware TEE is host-side work.
