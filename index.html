The mechanics

How a verifiable answer is made

Four steps, none of which asks you to believe a server. Each one produces bytes that a different machine can check on its own.

  1. 01

    Commit the model and the engine

    The weights and the inference engine are separate content-addressed RAREXT artifacts. A provider fetches both from a registry, verifies every shard, and runs exactly what it fetched — not a local build that could differ.

  2. 02

    Run it deterministically

    Decoding is seeded: greedy or sampled, temperature, top-k, top-p, min-p, typical-p, penalties, logit bias, a stop set. The same model bytes and the same seed produce the same tokens, on any machine, every time.

  3. 03

    Record a decode trace

    Every answer ships with the exact ids it decoded, the confidence per token, and the bound it ran inside. The trace is the claim; the text is a rendering of it.

  4. 04

    Verify by recomputation

    A reader re-derives the result from the trace, the model, and the seed. Lossy work — a quantized net, a codec — is a distance against a committed reference, measured, not asserted.

Verification is not the same as trust in an answer. Recomputation proves the bytes and the run are what was claimed. It does not prove the model is correct, safe, or unbiased, and it does not make a bad answer good. The protocol is built to say exactly that, and no more.

Measured, not promised

What the numbers actually say

The claim is checkable, so it is stated with its limits attached. These are measurements from the repository at this revision, not marketing figures.

3 representation kinds Exact bytes, a bounded metric against a committed reference, or a generative replay from a committed model and seed. Each is verified its own way.
1 verifier, 2 runtimes The same verifier runs in a browser tab and on a server and must return the same attestation from both bytes.
~8× cheaper than the naive pass The engine’s whole step against an independent output-projection pass on the same weights — and it agrees with a separately written full forward pass.

How to check the numbers yourself. The registry is anchored, and the mirror re-derives every AI rendition from the published bytes on your machine. Open the gallery, or verify the bundle, and watch the arithmetic happen rather than reading a summary of it.

Truth over hype

A verifiable answer is not a true answer. It is an answer whose bytes, run, and claim you can reproduce — and it only means something if the claim says what it does not cover.
