The network

web4 is the free-for-all layer.

Not a token, not a chain, not a browser. A network where any object, claim, or agent carries its own proof, and anyone with a device can hold bytes, verify work, and be paid for it. RAREXT is the protocol; ApesDaily is where the public meets it.

No gatekeeper for reading A payload is reachable from a hash and a mirror, not from permission.
No gatekeeper for verifying The verifier is a file you can read and run in a browser tab.
No protocol token Apps may launch tokens. The protocol's job is to make the launch checkable.

The honest definition

What “free” means here

The protocol does not bill you. That is a real property, and it is a narrow one. Here is exactly where it stops.

Writing, reading, verifying

No fee, no gate, no account. The reference registry is open source; run your own if you prefer ours.

One device, one copy

If your machine holds the bytes, it costs the protocol nothing — and it is a single copy. That is a backup that has not failed yet, not durability.

Durability is bought

More copies cost more disk somewhere. RAREXT makes the price explicit: k-of-n shards, published replica counts, retention challenges.

Physics still applies

Electricity, bandwidth, and the device are real costs. They are yours, and we do not pretend they vanished. Nothing here beats Shannon.

The commitment is forever. The bytes are rented. A publication's claim is permanent and recomputable; the storage that serves it is paid for by whoever chooses to hold it. When nobody does, the claim still verifies — you just have to supply the file.

The mechanics

Four steps, each one checkable

  1. 01

    Publish and sign

    Any file becomes a publication: a content hash, a kind, a meaning, and a signature from ECDSA-P256 or ML-DSA. The signing suite is recorded, so a reader knows what the proof is worth.

  2. 02

    Recompute, don't trust

    A deterministic verifier re-executes the claim. The shipped verifier runs unchanged in the browser and on the server and returns the same attestation from both.

  3. 03

    Anchor to a chain

    The Merkle root is anchored to a hash-linked log. The registry reads it back from an independent path before it says “confirmed” — a write is not a receipt.

  4. 04

    Replicate as shards

    Files are split into k-of-n Reed–Solomon shards and placed on distinct holders over HTTP. Each holder answers a nonce-bound Merkle challenge; lose holders up to n−k and any k rebuild the file, and a failed shard is repaired onto a spare.

Measured, not promised

Storage is real, inside stated limits.

Erasure-coded shards, signed placements, nonce-bound holder challenges, repair, and availability sampling run today. These are the measurements, including where they stop.

1 GiB · 394 MiB peak File-backed encode/decode. The latest rerun was 393 MiB; the in-memory path was 3,243 MiB.
1 GiB · 249 MiB peak Streamed over raw holder HTTP. The latest rerun was 242 MiB; holder peak was 94 MiB.
5,910 · 100% Puts and retrievals in a 604 s churn soak, with 145 repairs, zero failed re-audits, and 23 holder kills.
44 · 4 KiB Random samples detect 10% withholding at 99% confidence, for 176 KiB read.

What this does not prove. The sealed tier is not confidential until its envelope is reviewed. The soak is one machine on loopback with small payloads: it is not evidence about disks, power loss, TLS, or multi-writer coordination. Possession challenges are not retrievability proofs, and 100 GiB repair is unmeasured.

Truth over hype

Compression trades bytes for structure, fidelity, or compute. Erasure coding trades bytes for durability. Verification keeps both honest — and it only works if the claim says which trade it made.
